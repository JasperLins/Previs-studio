# 俯拍预设表观高度取景修复与预设名命名

## Goal

修复 45°俯拍/俯拍全景/鸟瞰三个俯拍系预设的人物画面占比过小的问题；预设创建的镜头直接以预设名命名。两项都是对已归档任务 10-24-shot-camera-presets（S9）的跟进，不新增接缝（命名在 S9 addShot 分支内）。

## Background（问题诊断，2026-10-24）

- 现行取景公式按物体**世界身高** H 预留画面竖向空间；但相机俯角 θ 越大，身高轴越贴近视线方向，人物在画面里的**表观高度** = `H×cosθ + 体厚×sinθ`（俯视只看到平面轮廓）。
- 标准人物（H=1.8、体厚≈0.3）在三个预设下的实际画面占比：45°俯拍 ~61%、俯拍全景 ~31%、鸟瞰 ~22%——与「预设机位的目的是展现人物不同机位展示」的产品意图不符（用户反馈）。

## Requirements

### R1 表观高度取景（src/shotPresets.js）

- 垂直取景距离改按 `apparent = height×cos(θ) + bodyDepth×sin(θ)` 计算：θ 取预设视线仰角 |pitch|（eye 类预设 |pitch|≤0.42，cos≈0.91+，影响可忽略）；bodyDepth：person = 0.3×scale[2]（与肩宽 0.55×scale[0] 同套路），几何体 = scale[2]（depth）。
- 水平复核（16:9、width）保持现状。
- 预设表调参（framing）：high_45 保持 1.35（占比 61%→~74%）；top_down 1.6→2.0（→~50%，保留「全景」上下文）；birdseye 1.45→3.2（→~31%，高度约 2.3m、人物平面轮廓清晰占画面 1/3）。
- 「当前视角」与 eye 类预设行为基本不变（公式对 θ 小的预设数值变化 <10%）。

### R2 预设名命名（App.jsx，S9 接缝内）

- `addShot(presetId)` 中 override 生效时：`name: uniqueShotName(shots, 预设label)`（如「45°俯拍」，重复自动「 2」后缀）；未选预设/当前视角仍用 defaultShotName。
- PATCHES.md / base-audit.md 的 S9 行补记命名改动。

## Acceptance Criteria

- [ ] 俯拍三预设对标准人物的画面竖向占比（按编译器同款投影口径计算）落在目标区间：45°俯拍 65–80%、俯拍全景 45–60%、鸟瞰 25–40%。
- [ ] 平视类预设（front_medium/side_track 等）机位变化 ≤10%（回归不受扰动）。
- [ ] 预设创建的镜头名为预设名（重复加序号）；「当前视角」命名与旧逻辑一致。
- [ ] `node --test src/shotPresets.test.js` 全绿（更新受影响断言 + 新增占比断言）；全仓 `node --test` 全绿；`npm run build` 成功。
- [ ] 浏览器实测：三个俯拍预设摄像机视角下人物明显、构图符合预期（截图留档）。

## Non-Goals

- 不改面板 UI/预设清单/交互；不做机位实时预览。
- 「机位词」编译器的景别推断口径（按世界身高投影）不动——它是既有语义，本任务只改预设取景。
