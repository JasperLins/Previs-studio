# 00 · 项目总览与决策记录

## 背景

AI 漫剧课堂上，学生不会写空间描述：手绘站位图喂给豆包/即梦识别失败，纯文字描述场景又慢又错。结论（2026-10-23 课堂调研）：扩散模型「参考」图可以、「执行」图不行；正确路线是把空间信息存成**结构化状态**，再由程序把状态编译成机位投影描述与提示词。我们自建 3D 导演台成本过高，选定基于 MONOFORM 二次开发：它有骨骼人物、IK、多镜头、关键帧与 MP4 导出，缺的正是我们要补的三件——导演机位图的读图语言、轴线/视线等标注、提示词编译。

## 已拍板决策（ADR 摘要）

| # | 决策 | 理由 |
|---|---|---|
| A1 | 基于 MONOFORM fork 二次开发，不另起项目 | 它最贵的部分（骨骼/IK/关键帧/导出）不重造；我们的价值是加法层 |
| A2 | 不做独立 2D 编辑器；2.5D = 引擎式「顶视正交编辑视图 + Gizmo 标注层 + 顶视符号替换」 | Cocos/Unity 等引擎的成熟范式：同一场景、多视图、标注是编辑层 Gizmo。独立画布会引入同步与双套交互成本 |
| A3 | 符号替换只针对四类：人物、门、窗、墙（薄方块） | 垂直物体顶视塌成线、人物顶视读不出朝向；其余家具顶面即其符号 |
| A4 | Fork 纪律：适配层唯一入口、新文件为主、接缝台账（PATCHES.md） | 上游无版本标签、单 main 分支；纪律保证可同步、可退出 |
| A5 | 提示词只出中文，分层输出，几何层自动、动作层人工 | 目标平台是豆包/即梦；程序不替人编表演 |
| A6 | 开发管理用 Trellis + ZCode | 用户指定 |

## 架构总图（文字版）

```
MONOFORM 原有层（尽量不动）
  App.jsx 状态：objects[] / camera / shots[] / selectedId / keyframes…
  Viewport.jsx：R3F 画布，PrimitiveModel 按 type 渲染，CameraModel 机位
        │  （只经适配层读写）
我们新增层 src/diagram/
  stateAdapter     上游状态 ⇄ 镜头数据模型（唯一耦合点）
  TopViewControls  顶视正交编辑相机预设 + 地面约束拖拽
  gizmos/          视锥、标签牌、轴线、视线、路径、幽灵机位（编辑层渲染）
  symbols/         人物/门/窗/墙 的顶视符号替换渲染
  promptCompiler/  投影计算 → 术语映射 → 分层提示词（纯函数）
  exportDiagram    只读机位图导出渲染（可选，P2 评估）
```

## 范围与分期

- P0：顶视正交视图、地面约束拖拽、机位视锥+标签牌、四类符号替换。
- P1：轴线与越轴警告、视线层、走位/机位路径、幽灵机位、图层开关。
- P2：提示词编译器、镜头描述卡、提示词导出；（可选）干净机位图导出。
- P3：灯光 Gizmo 符号化、墙段新类型（需单独评审）。

非目标：AI 生图/生视频、多人协作、账号与云同步、对外发布。
